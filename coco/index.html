Aug 2026 / AI governance / Australia

Teaching AI agents some manners

How I designed the MVP of Coco, a gateway that checks every move an AI agent makes against company policy, before it happens. From a technical draft flow to a product risk teams can actually use.

client
Coco AI, Melbourne
role
Product designer
team
Founders, engineers, a designer-engineer
status
MVP live, full flow

01 the problem

AI agents can move money now. Who checks them first?

Companies are handing more and more work to AI agents. Some of that work touches real cash: paying vendors, approving applicants, closing fraud alerts. One wrong move can be expensive, and very hard to undo.

Coco sits between the agent and the action. A company turns its rules and policies into behavioural contracts. Before an agent acts, Coco checks the action against them and hands back a verdict, and every verdict lands in an audit log the agent can't touch. So teams can let agents do more, with less risk and less babysitting.

02 the brief

A smart idea, a draft flow and a lot of jargon

The founders came with a clear idea and a draft flow. My job: turn it into a real product. Set up the design system, sit with the team until I understood what every module actually does, then shape the screens around it.

The tricky part? Coco is deeply technical, but not everyone using it is an engineer. Risk and compliance people, who may never open a terminal, still need to review escalations, read audit trails and trust the verdicts.

Contracts, verdicts, SDKs

Every concept needed a plain-language name and a clear home.

Two audiences

Setup is for developers. Daily review is for people who are not.

Small but complete

It is an MVP, yet from sign-up to the first verdict there are no dead ends.

03 product map

Mapping everything before drawing a single screen

Before any pixels, I mapped the whole MVP: a six-step onboarding that ends with an API key, then a workspace where each project carries its own contracts and audit trail.

Onboarding, 6 steps

  • Create your organization
  • Name your first project
  • What Coco does
  • Select a framework
  • Choose your plan
  • Get your API key
  • Agent connected, off to the dashboard

Workspace

  • Dashboard: all projects, last 30 days
  • Project: overview, escalate, audit logs, evaluation, contracts, controls
  • SDK and API keys
  • Settings: members, usage costs, billing, 2FA

04 onboarding

Six steps to a working agent

Sign in, create your organization, name a project and pick its workflow family: payments, KYC, AML and fraud, or custom. Then choose what your agent runs on, from Claude Code and Cursor to LangGraph and n8n, and Coco writes the right SDK snippet for you. Pick a plan, copy the key, wire up the agent in your terminal. Done, straight to the dashboard.

05 dashboard

The moment the numbers start moving

This is the first screen after setup. Verdict totals use the same four colors everywhere, so a spike in red reads instantly. Recent alerts show what needs you, and every project sits below with its contracts, verdicts and escalations.

06 escalate & audit

Humans stay in the loop

Some actions should never happen without a person saying yes. A $128,000 payment. Approving a tier 3 applicant. Those become escalations: each card shows the contract and the exact action, with Approve and Reject side by side, plus an SLA badge when a review is running late.

Audit logs record every verdict, and they are append-only, so the agent can't write there. Open any row and you get what happened in plain English first, then which checks passed and the contract behind it. The developer view is folded away underneath, for the people who want it.

07 contracts & evaluation

Turning policy documents into rules agents actually follow

Contracts are the heart of Coco. A bank or company uploads its policies, things like tax rules, compliance guidelines and do's and don'ts, and Coco's AI drafts a behavioural contract from each clause. Think of them as skills for an agent. Every contract cites its source, and a human reviews it before it goes live.

Evaluation closes the loop. An LLM scores each agent while people rate single verdicts from Critical to Excellent. Together they show where contracts are too tight or too loose, so both the rules and the agents get better over time.

08 configure

The settings nobody brags about (but everyone needs)

Controls define the metrics used to judge an agent: which step they watch (tool or LLM), when they run (pre or post) and where (server or SDK). SDK and API keys manage how Coco connects to each environment. Settings covers members and roles, usage costs, billing and two-factor authentication.

09 design system

One system for brand, product and code

I built Coco's design system together with a product designer and a software engineer in Australia, so design and code speak the same language. It starts from the brand guideline (a violet core on warm paper, Cal Sans type) and carries all the way to product tokens in light and dark.

The four verdicts became first-class semantic tokens, each with 60 and 10 tints. And the color names follow a Dragon Ball Z naming scheme. Yes, really. It keeps them easy to remember across products ;)

10 team

Built between Vietnam and Melbourne

A distributed team with members in Vietnam and Melbourne, working fully in English and meeting weekly with the founders and engineers to land on final solutions. The first version is live, and the full flow works end to end.
